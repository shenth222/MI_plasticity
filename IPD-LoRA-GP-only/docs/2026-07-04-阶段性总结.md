# Goodput-LoRA 项目阶段性总结（2026-07-04）

状态：E1（全预算 GLUE 全表）完成；E3（效率分析）完成；Plan B（低预算受控）进行中并发现配置混淆待修。
算力：10 × RTX 3090（24GB），实测常有 4 张被他人占用。
基础模型：DeBERTa-v3-base；本地 GLUE 数据。

---

## 0. 摘要（TL;DR）

- 我们把旧工作（IPD-LoRA → GP → GP-only）**重构为一个统一、可复现的 LoRA 预算分配对比框架**（Goodput-LoRA harness），支持 4 种方法在**同数据 / 同预算 / 多 seed / 同日志口径**下公平对比：
  - `lora`（静态均匀）、`gora`（训练前一次性梯度重要性）、`goodput`（在线动态，本文方法）、`adalora`（训练中 SVD 重分配，peft 官方）。
- **核心实证结论（对论文原假设不利，但重要）**：在 GLUE + DeBERTa、同预算下，
  1. **精度维度**：`goodput` 与静态 `lora` 在 8 个任务上**全部统计打平**（差异都在 std 内）；
  2. **效率维度**：`goodput` 也**没有更优**——收敛不更快（RTE 到阈值 650 步 vs lora 364 步）、rank-step 反而更多、wall-clock 与 lora 相当；唯一成立的效率故事是"简单方法（lora/goodput）比 AdaLoRA 省 1.7–2× wall-clock"，但此处 lora 与 goodput 并列。
- **Plan B（低预算翻案尝试）初步信号也不利**：RTE 预算砍到 1/3（144）时 `goodput` 反而最差（86.88 vs lora 88.45）；**但该结果被一个写死的启动配置 `initial_active_rank=8` 污染**（低预算下相当于 4× 超支预算），需修正后重跑才可信。
- 当前处在**方法是否"有救"的判定关口**：待修正后的 Plan B + 尚未做的 E4（信号有效性）出来，再在「A: 低预算/等精度更省 有救」「C: 转 R4 负结果严谨化叙事」之间决策。

---

## 1. 方向演变（Why 重构）

旧工作两个实测瓶颈（见 `docs/2026-06-28-research-proposal.md`）：
- **B1 方法过复杂**：I（重要性）/P（可塑性）/G（Goodput）三套信号信息高度重叠。
- **B2 效果不理想且不稳定**：单 seed、无同预算 baseline，`mean_goodput_rank_step` 常为负（后期用噪声驱动 rank 抖动）。

据此确立方向：**不再修补"更好的分配器"，而是（a）用 Goodput 统一视角重定义目标与评测，（b）沿"分配时机"轴做受控研究，（c）极简化（单超参=预算）。** 精度只需"可比"，卖点押在效率/Goodput（proposal R2）。

## 2. 工程与代码成果

### 2.1 统一 harness（4 方法同框架）
- `train_ipd_lora.py`：主训练入口，`--method {lora,gora,goodput}` 分发；共享数据/评估/日志。
  - `lora`：`set_uniform_rank` 均匀分配。
  - `gora`：`compute_pretrain_gradient_importance` + `allocate_rank_by_score` 训练前一次性分配。
  - `goodput`：在线周期性估计每模块 Goodput（proxy/probing）并重分配。
- `train_adalora.py`：peft 官方 AdaLoRA 独立入口，**复用同一数据/评估/预算口径**，产出同 schema 结果；注入 72 模块 = 预算 432，与其它方法严格对齐。
- **预算守恒（公平性关键）**：`_waterfill_extra_ranks` 保证任何方法把整份 rank 预算用满（模块触顶时余量再分配），使"同预算"对比成立。

### 2.2 脚本
- `scripts/run_glue.sh`：单次实验（method × task × seed），env 可覆盖预算/LR/epochs；`OUT_PREFIX` 支持把一批实验写到独立结果根目录（低预算隔离用）。
- `scripts/run_multiseed.sh`：单任务 4方法×多seed 并行扫描，多 GPU round-robin，**容错 drain（单 job 失败不中止整批）**。
- `scripts/run_queue.sh`：任务队列，等前置 PID 释放 GPU 后依次跑并自动汇总（曾用它一夜跑完 stsb/sst2/qnli/mnli/qqp）。
- `scripts/run_budget_sweep.sh`：Plan B 低预算受控 sweep（多预算档 × 多任务，结果隔离到 `outputs/budget_r*`）。
- `scripts/aggregate_results.py`：按任务标准主指标汇总 mean±std（**CoLA→MCC、MRPC/QQP→F1、STS-B→pearson、其余→acc**），输出 `summary.md/csv`。
- `scripts/efficiency_report.py`：E3 效率报告，从 `training_log.jsonl` 重建学习曲线，算 best/AULC/steps-to-threshold/累计 rank-step/wall-clock/goodput，输出 `efficiency.md`。

### 2.3 过程中修复的关键问题
- **AdaLoRA 从"稻草人"修成合格强 baseline**：用 lr=2e-4（与他人一致）时 AdaLoRA 在 `tinit` 后塌缩到多数类（RTE 60.89%）；诊断确认根因是**学习率**（非精度、非正交权重、非 bf16），AdaLoRA 需 lr≈1e-3 → 修正后 RTE 87.73。`run_glue.sh` 加 `LR_ADALORA`（默认 1e-3）。
- **STS-B 回归路径**：`num_labels=1` + 标签转 float + MSE（`select_primary_metric`/建模 stsb 门控），CPU 端到端验证通过。
- **主指标口径**：`evaluate_model` 引入 `select_primary_metric`，best-checkpoint 选择与汇总统一按 GLUE 标准指标（MRPC 从 91.01acc 变 93.53 F1，结论不变）。
- **操作教训**：曾在 sweep 运行时编辑 `run_glue.sh`，bash 按字节偏移读运行中脚本导致 wrapper 尾部错乱（训练本身没事）。已在脚本注释中警告"勿编辑运行中脚本"。

## 3. 实验结果

### 3.1 E1：全预算 GLUE 全表（预算 rank=432，3 seed，mean±std）

| 任务(主指标) | lora | gora | **goodput（本文）** | adalora |
|---|---|---|---|---|
| RTE (acc) | 87.24±0.90 | 87.00±0.78 | 87.00±0.78 | **87.73±0.59** |
| MRPC (F1) | 93.53±0.25 | 93.52±0.22 | **93.61±0.10** | 93.29±0.15 |
| CoLA (MCC) | **70.92±0.30** | 69.66±0.22 | 69.83±0.25 | 70.67±0.11 |
| STS-B (pearson) | 90.77±0.60 | 90.90±0.18 | 90.91±0.34 | **91.76±0.06** |
| SST-2 (acc) | 95.68±0.24 | **95.80±0.27** | 95.49±0.19 | 95.57±0.11 |
| QNLI (acc) | 94.23±0.04 | 94.34±0.13 | 94.19±0.12 | **94.45±0.13** |
| MNLI (acc) | 90.26±0.11 | 90.34±0.11 | 90.42±0.07 | **90.58±0.08** |
| QQP (F1) | 88.76±0.15 | 88.76±0.20 | 88.62±0.18 | **88.78±0.07** |
| 可训练参数 | ~1.0M | ~1.1M | ~1.1M | **~2.0M** |
| wall-clock | 1× | 1× | ~1× | **1.7–2×** |

- `goodput` vs `lora`：8 任务符号互有胜负（mrpc/stsb/mnli 微弱领先，rte/cola/sst2/qqp/qnli 微弱落后），**全部落在 std 内 → 统计不可区分**。
- `adalora` 在 rte/stsb/qnli/mnli/qqp 微弱最高，但代价 2× 参数 + 1.7–2× wall-clock。

### 3.2 E3：效率报告（从现有日志计算，未重跑）

RTE（阈值 = 0.97×best = 85.8%；steps↓=收敛快，AULC↑=好）：

| 方法 | best% | AULC% | steps@0.97 | 累计rank-step@0.97 | wall_s | goodput/wall |
|---|---|---|---|---|---|---|
| lora | 87.24 | 83.59 | **364±37** | **1.49e5** | 637 | **1.370** |
| gora | 87.00 | 83.80 | 364±74 | 1.49e5 | 643 | 1.354 |
| **goodput** | 87.00 | 83.29 | 650±160 | 2.95e5 | 648 | 1.342 |
| adalora | 87.73 | 79.12 | 702±64 | (缺记录) | 852 | 1.030 |

- **"早期在线重分配加速收敛"假设被证伪**：goodput 到阈值更慢（650 vs 364 步）、rank-step 更多（早期从 rank=8 起步超支）。
- 唯一效率故事：lora/goodput 比 AdaLoRA 收敛快、wall-clock 省——但 goodput 不比 lora 强。
- MNLI：四方法 AULC 89.7–89.9 全打平；steps-to-threshold 因阈值过高退化（需调低）。

### 3.3 Plan B：低预算受控（进行中）

RTE @ 预算 144（avg rank 2）：

| 方法 | acc@144 | acc@432 | 参数@144 |
|---|---|---|---|
| lora | **88.45±0.78** | 87.24 | 0.33M |
| gora | 88.33±0.17 | 87.00 | 0.39M |
| adalora | 88.09±0.51 | 87.73 | 1.33M |
| goodput | **86.88±0.61** | 87.00 | 0.39M |

- 预算砍到 1/3：lora 反升（低秩正则更好），goodput 掉到最差（比 lora 低 ~1.6%，超 std）。
- **⚠️ 被配置混淆**：`goodput` 的启动秩 `initial_active_rank=8` 在 `run_glue.sh` 写死，低预算(avg 2)下相当于 4× 超预算 warmup（证据：goodput rank-step 4.23e5 比其它多 25%）。**修正前不能据此定论。**
- 其余低预算任务（mrpc/cola @ r2、rte/mrpc/cola @ r1=预算72、mnli @ r2）仍在后台跑。

## 4. 核心发现

1. **同预算下，分配时机/信号复杂度对最终精度几乎无影响**（GLUE + DeBERTa）：lora/gora/goodput 三者处处打平，adalora 仅以 2× 成本换 ~0.2 均值优势。
2. **在线动态分配（goodput）相对静态 lora 在精度与效率两条轴上均无优势**；其早期高秩探索反而拖慢收敛、多耗 rank-step。这与 proposal 的 R4 场景（"在线不优于静态则坦诚报告为有效性边界"）吻合。
3. **AdaLoRA 的"更好"极不划算**：2× 参数、1.7–2× wall-clock、收敛更慢，换来接近噪声的精度提升。
4. 结构性洞察：同预算+同步数 ⇒ 累计 rank-step 恒定，动态方法只能靠"更快收敛"取胜，而数据显示它并未更快。

---

## 5. 仍存在的问题

- **P1（方法层）**：goodput 在标准 setting 下无精度/效率优势——这是当前最根本的问题，决定论文能否成立。
- **P2（Plan B 混淆）**：`initial_active_rank=8` 写死，低预算下不公平；需改为随 target 缩放（如 = target_rank）后重跑，Plan B 结论才可信。
- **P3（E4 缺失）**：尚未验证信号有效性——`ema_G` 与未来真实 module gain 的相关性及其随训练的衰减。没有它，负结果缺"为什么不 work"的机制解释。
- **P4（工程口径）**：
  - `train_adalora.py` 未记录 `active_total_rank`，AdaLoRA 的累计 rank-step / rank-step goodput 算不出（E3 表里显示"缺记录"）。
  - MNLI 的 steps-to-threshold 阈值过高退化，需按任务调低 `--thr-frac`。
  - 旧的全预算 mrpc/qqp 的 `training_log.jsonl` 里 `eval_accuracy` 记录的仍是 accuracy（非 F1），做曲线分析时口径需注意（`select_primary_metric` 修复仅对新 run 生效）。
- **P5（现代场景缺失）**：E2（LLaMA-3.1-8B + commonsense/数学）未做，reviewer 会在意。
- **P6（STS-B 覆盖）**：回归路径已修并 CPU 验证，但尚未在完整 GPU 训练/低预算/大模型下端到端验证正确性与稳定性。

## 6. 下一步计划

### 6.1 立即（判定方法是否"有救"）
1. **修 `initial_active_rank` 随预算缩放**（`run_glue.sh` goodput 分支：`--initial_active_rank` 用 `${TARGET_RANK}` 或 `min(2×target, max)`），**等当前 Plan B sweep 结束或停掉后**再改（勿编辑运行中脚本）。
2. **干净重跑 Plan B 低预算**（预算 144 / 72，小任务 + mnli），得到公平的"稀缺预算下动态是否反超静态"结论。
3. **做 E4 信号有效性分析**：从 goodput run 的内部日志（或补一条 ema_G / 真实 module gain 记录）算 Spearman 相关与衰减曲线，解释 P1。
4. **补 AdaLoRA `active_total_rank` 日志**（或解析近似），补全 E3 的 rank-step 维度。

### 6.2 分支决策（依 Plan B + E4 结果）
- **路线 A（还有救）**：若修正后 goodput 在低预算/等精度维度反超 lora（"等精度更省预算"），则主打效率叙事，补 E2 大模型验证。
- **路线 C（负结果严谨化，proposal R4）**：若仍不优于静态，则把工作定位为**"动态 rank 分配有效性边界的严谨受控研究"**——统一 Goodput 视角 + 分配时机轴 + E4 机制解释，负结果 + 诊断也构成贡献。
- 两条路线都需要：CoLA→MCC / MRPC→F1 口径（已就绪）、多 seed（已就绪）、效率协议（已就绪）。

### 6.3 中期
- 若走 A：E2（LLaMA-8B，bf16 + gradient checkpointing，commonsense/GSM8K），与 GoRA 同台。
- 用 academic-paper skill 起草大纲与初稿（proposal M6）。

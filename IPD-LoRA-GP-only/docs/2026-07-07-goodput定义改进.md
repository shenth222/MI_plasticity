# Goodput 定义改进：让它能公平衡量全部 4 个 baseline（Pollux 视角）

日期：2026-07-07
背景问题（你的疑问）：当前的 **module Goodput** 只有 goodput 方法内部才算得出来，没法拿去衡量 lora / gora / adalora；而现在唯一跨方法的效率指标只有 wall-clock。如何参考 Pollux 改进定义？

---

## 1. 症结：你把「分配信号」当成了「评测指标」

当前定义
```
G_m = ΔL_val · share_m / (r_m · K)          # 每模块、每评分窗
```
是一个 **per-module 的分配信号**：它的作用是回答"下一步该把秩加到哪个模块"。它必须靠 probing/proxy 现场估计，因此**只有 goodput 方法会产生它**——拿它去比 lora/adalora 天然不可能。这正是"衡量不了另外三个 baseline"的根源。

**解决办法：把两个不同作用域的对象分开，各司其职。**

| 对象 | 作用域 | 谁能算 | 用途 |
|---|---|---|---|
| **module Goodput** `G_m` | 每模块（内部信号） | 只有 goodput | 驱动分配（"秩往哪放"）。**不该**当跨方法效率指标；其有效性由 **E4** 检验 |
| **evaluation Goodput** `G_eval` | 全局（一个标量） | **全部 4 方法** | 论文主指标（"同样学到东西花了多少资源"） |

---

## 2. Pollux 的定义，以及如何映射到 rank 分配

Pollux（Qiao et al., OSDI'21）最大化的 goodput 是**系统吞吐 × 统计效率**的乘积：

```
GOODPUT(资源分配) = THROUGHPUT(examples/sec) × STATISTICAL_EFFICIENCY(progress/example)
                  = 真实训练进度 / 秒
```
- THROUGHPUT：系统项——单位时间处理多少样本（受资源、batch 影响）。
- STATISTICAL_EFFICIENCY：统计项——每个样本带来多少"有效学习"，用梯度噪声尺度（GNS）估计（batch 越大吞吐越高，但每样本统计效率递减）。
- 关键：两者**相乘**才是你真正想要的东西，且可以拆开归因"赢在系统还是赢在统计"。

**映射到我们的问题**：我们的"资源"不是 GPU/batch，而是**适配预算 = 秩**（以及它在模块间、时间上的分布）。同构地：

```
G_adaptation = THROUGHPUT_adapt × EFFICIENCY_adapt
THROUGHPUT_adapt  ~ 单位时间消耗的预算（rank-step/sec，或 examples/sec）    ← 系统项（AdaLoRA 的 SVD 开销在此暴露）
EFFICIENCY_adapt  ~ 单位预算带来的验证损失下降（progress / rank-step）       ← 统计项（分配的秩是否被真正用上）
乘积 = ΔL_val / 秒
```

## 3. 改进后的定义（三层，全部可跨 4 方法测）

### 3.1 主指标：evaluation Goodput = 进度 / 资源（三种货币）
对任意方法，用它自己的验证损失曲线 + 资源消耗曲线：
```
G_eval = ΔL_val_total / Cost
Cost ∈ { rank-step:  ∫ Σ_m r_m(t) dt        # 容量/统计成本（实际花掉的预算）
         wall-sec:   总训练墙钟秒            # 真实系统成本（AdaLoRA 1.7–2× 在此）
         FLOP:       ∫ Σ_m r_m(t)(d_in+d_out) dt }  # 硬件无关算力
```
这正是仓库里已有的 `compute_global_goodput`——**它本来就是方法无关的**，只是目前没给 4 方法都接上（`train_adalora.py` 甚至没记录 `active_total_rank`）。所以"只有 wall-clock"是**工程没接线**，不是定义做不到。

**最好读、最不可 game 的头条形式**（等价于 Pollux 的"达到目标质量所需资源"）：
- **budget-to-threshold**：达到目标精度所消耗的累计 rank-step；
- **time-to-threshold**：达到目标精度的墙钟时间。
（已在 `efficiency_report.py` 里算，需补 adalora 的 rank 记录。）

### 3.2 统计效率项：有效秩利用率（本文最 Pollux、最能解释结果的新指标）
Pollux 的统计效率我们用 **LoRA 原生的"分配的秩到底用没用上"** 来对应。对每个适配模块，取更新 ΔW = B·A（尺度无关），奇异值 σ_i：
```
p_i   = σ_i / Σσ_j
erank = exp(−Σ p_i ln p_i)            # 实际用到的秩（Roy & Vetterli 2007）
util  = erank / r_alloc ∈ (0,1]        # 利用率
```
util→1：分配的秩被铺满使用（预算用得值）；util≪1：更新其实塌在少数方向上（预算浪费，这个模块少给点几乎无损）。
**对 4 方法都能后验算**（脚本 `scripts/effective_rank.py`）。它让你把 `G_eval = 吞吐 × 效率` 真正拆开，并**从机制上解释**为什么分配不分配一个样。

### 3.3 分配信号有效性（解释为什么 online == static）
`module Goodput` 到底是不是有用信号，由 **E4**（`scripts/e4_signal_validity.py`）检验：持续性、预测力、截面集中度、lag 衰减。

## 4. 已经跑出来的证据

### E4 信号有效性（现有全预算 goodput 日志，3 seed）
| task | entropy(1=均匀) | persist@lag1 | predict@lag1 |
|---|---|---|---|
| rte | 0.90 | -0.02 | +0.17 |
| mrpc | 0.86 | -0.26 | +0.04 |
| cola | 0.84 | -0.23 | -0.00 |
| mnli | 0.84 | -0.21 | -0.05 |
| sst2 | 0.78 | -0.20 | -0.04 |
| qnli/qqp/stsb | 0.82–0.88 | -0.17~-0.26 | ≤0.07 |

判读：截面熵≈0.8–0.9（各模块 goodput **几乎均匀**，没差异可利用）；持续性≈0 甚至略负（模块 goodput 在窗口间**基本是白噪声**）；预测力≈0（分配所依据的 ema_G **预测不了**下一窗真实收益）。→ 在线重分配既无杠杆也无可追踪目标，**必然打平静态均匀**。这是 null result 的直接机制证据。

### 有效秩利用率（统计效率项，全预算 r=6）
| task | lora util | gora util | goodput util |
|---|---|---|---|
| rte | 0.707 | 0.699 | **0.742** |
| cola | 0.669 | 0.678 | **0.740** |
| mnli | 0.732 | 0.737 | **0.793** |

判读：goodput 的利用率**确实略高**（把秩放得更"用得上"），但**没有转化为精度**——因为 r=6 预算下任务已容量饱和，利用率 0.67→0.79 的差异淹没在噪声里。这与 E4 互补：分配有微弱的正确性，但在这个 regime 下不解决问题。

---

## 6. 一句话结论

module Goodput 是**分配信号**，不该拿去比 baseline；跨方法的效率评测应改用 **Pollux 式 `G_eval = ΔL_val / {rank-step, wall, FLOP}`（+ 到阈值预算/时间）作系统项、有效秩利用率作统计效率项**——这三样对 4 方法都可测，且 E4 + 利用率已经能从机制上解释"在线分配为何打平静态"。

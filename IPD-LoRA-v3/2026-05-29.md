## 3.2 算法与实验修正：稳定性/可解释性增强（`dbce5f7`）

### 做了哪些更新

#### A) P 指标解耦：引入 `plasticity_task_weight`
- 改动位置：
  - `train_ipd_lora.py`：新增 CLI 参数 `--plasticity_task_weight`（默认 `0.1`）
  - `ipd_lora.py`：`compute_plasticity_scores(..., task_weight=0.1)`，并令 `w_task = max(0, task_weight)`
  - `PARAMETERS.md`：补充该参数说明
  - `rte.sh`：显式传入 `--plasticity_task_weight 0.1`
- 直接效果：
  - 将 P 分子中 `max(ema_I,0)` 的影响从固定值变为可控权重。

#### B) 象限划分改进：由阈值比较切换为 Top-K mask
- 改动位置：`ipd_lora.py`
  - 新增 `_high_mask_by_quantile(...)`
  - `update_quadrants_and_budget(...)` 内由
    - `ema >= quantile_threshold`
    - 改为基于排序后固定数量的高位 mask。
- 直接效果：
  - 避免阈值边界附近大量并列值导致“高位模块数量漂移”。

#### C) 运行态持久化：best/final 模型同步保存 IPD 状态
- 改动位置：`train_ipd_lora.py`
  - 新增 `snapshot_ipd_runtime_state(...)` / `restore_ipd_runtime_state(...)`
  - best model 保存时同步写出 `ipd_runtime_state.json`
  - 加载 best 权重后恢复相应 IPD 运行态
  - final model 同样写出 `ipd_runtime_state.json`
- 直接效果：
  - 避免“权重来自 best step，但 rank/quadrant 状态仍是最后一步”导致的不一致。

#### D) 图分析口径修正：引入模块反事实收益 `module_gain`
- 改动位置：`plot_ipd_results.py`
  - 新增 `_attach_counterfactual_module_gain(...)`
  - 将象限统计和图中关键指标从 `avg_loss_decrease` 迁移为 `avg_module_gain` / `avg_module_gain_per_rank`
  - 图标题与轴名称同步更新为 counterfactual 口径
- 直接效果：
  - 降低将“全局未来验证损失”粗暴分配到模块导致的解释偏差。

#### E) RTE 参数收敛方向调整
- 改动位置：`rte.sh`
  - `target_rank: 8 -> 6`
  - 增加 `--plasticity_task_weight 0.1`
- 直接效果：
  - 在不改训练框架前提下，向更保守预算与更稳健指标耦合方向调参。

### 解决了哪些问题
- **问题1：P 指标可能过度依赖 I，形成 I->P 信息泄漏**
  - 通过 `plasticity_task_weight` 降低耦合强度，使 P 更接近“资源效率”而非 I 的镜像。
- **问题2：分位数阈值法在离散/并列值下导致象限规模不稳定**
  - 通过 Top-K mask 固定高位样本数，提高 rank 分配可预期性。
- **问题3：best checkpoint 与调度状态脱节**
  - 通过 runtime state 持久化 + 恢复，保证复现/部署时状态一致。
- **问题4：象限收益图存在归因口径偏差**
  - 改用模块级 counterfactual gain，提升图表对决策的解释有效性。

## 5. 对 PPT 友好的技术主线（可直接拆页）

### 主线 1：从“静态 LoRA”到“动态预算 LoRA”
- 固定 rank -> 模块级动态 `active_rank`
- 依据 I/P 象限对 rank 与更新频率进行联合调度
- 在预算约束下优先保留高价值模块

### 主线 2：评分与调度的工程可落地
- I：消融损失增量（exact/grouped）
- P：多代理资源效率（含 optimizer 状态）
- 稀疏评分覆盖计划：兼顾成本与覆盖率

### 主线 3：可复现与可解释
- best/final 模型同步保存 IPD 运行态
- 模块级日志 + 象限图谱 + counterfactual 增益分析
- 参数文档齐全，便于复现实验与答辩说明

## 6. 建议在汇报中强调的“问题-改进-收益”闭环

1. **问题：I/P 耦合可能带来偏置**  
   **改进：** `plasticity_task_weight` 参数化  
   **收益：** P 指标语义更纯，调度更稳。

2. **问题：分位阈值在边界值上不稳定**  
   **改进：** quantile threshold -> Top-K mask  
   **收益：** 象限模块数稳定，预算分配可预测。

3. **问题：best 权重与策略状态不一致**  
   **改进：** 保存并恢复 `ipd_runtime_state.json`  
   **收益：** 评估复现一致，部署风险下降。

4. **问题：象限收益图归因过粗**  
   **改进：** 引入模块级 `module_gain`  
   **收益：** 可解释性更强，保留/剪枝策略更有证据链。

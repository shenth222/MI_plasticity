# IPD-LoRA v3/v4 问题与进展汇报

日期：2026-05-31

本文档汇总近期在 GLUE RTE 任务上围绕 IPD-LoRA 训练、评估、象限策略与可视化分析中发现的问题，以及已经采取或建议采取的解决方案。内容按问题类别合并整理，便于后续制作 PPT。

## 标题：训练过程中模型模式未正确恢复

### 原因/现象

在 IPD 重要性打分过程中，模型会被切换到评估模式。早期版本中，打分结束后没有显式恢复训练模式，导致部分训练步骤可能在评估模式下继续反向传播。

该问题会造成训练行为与预期不一致，例如 dropout 等训练时行为被关闭，影响模型泛化和训练稳定性。

### 解决方案

在每次 IPD 打分结束后，显式调用 `model.train()`，确保后续训练步骤恢复到训练模式。

该问题已修复，属于高优先级实现问题。

## 标题：最终指标未使用最佳 checkpoint

### 原因/现象

早期实验中，训练过程虽然会保存 `best_model`，但最终评估和结果导出仍使用最后一轮模型。

在 RTE 小样本任务上，后期很容易过拟合，导致最终准确率低于训练过程中的最佳准确率。例如早期实验中 best accuracy 明显高于 final accuracy，造成结果被低估。

### 解决方案

训练过程中记录最佳模型权重，并在训练结束后回载最佳权重，再进行 final evaluation 和 final model 导出。

后续进一步发现，IPD-LoRA 中的 `active_rank`、`update_interval`、`quadrant` 等运行态不是模型参数，不能只依赖 `state_dict` 恢复。因此又补充了 IPD 运行态快照机制，在 best checkpoint 中同时保存和恢复 IPD 状态。

当前版本中，best accuracy 与 final accuracy 已能保持一致，说明该问题已基本解决。

## 标题：训练后期过拟合明显

### 原因/现象

RTE 数据量较小，训练轮数较多时，模型在中后期容易出现验证集性能下降。最新实验中，最佳准确率出现在较早 epoch，而训练末期验证准确率明显回落。

虽然 best checkpoint 回载可以保证最终汇报不被最后一轮拖低，但训练后半段仍存在大量无效甚至有害训练。

### 解决方案

保留 best checkpoint 汇报机制，避免最终结果被后期过拟合影响。

建议后续加入基于验证集的 early stopping，或者在实验脚本层面根据验证集表现提前停止训练。由于当前用户要求暂不减少 epoch，本阶段未修改 `num_train_epochs`，但该问题仍应作为后续稳定性优化方向。

## 标题：序列长度设置偏短

### 原因/现象

早期 RTE 实验使用 `max_length=128`。RTE 是句对推理任务，较短的最大长度可能截断关键信息，影响模型上限。

该问题不会增加模型参数量，但会影响训练和评估时输入信息完整性。

### 解决方案

将 `max_length` 从 128 调整为 256，与更常见的 GLUE/RTE 微调设置对齐。

该修改已加入当前实验脚本。

## 标题：IPD 重要性打分覆盖不足

### 原因/现象

早期版本中，每次只对部分 LoRA 模块进行重要性打分，且总打分次数较少，导致部分模块在整个训练过程中从未获得有效的 I 分数。

这会造成象限划分和 rank 分配存在系统性偏差。一些模块可能因为没有被打分而被误判为低重要性，影响策略可信度。

### 解决方案

新增参数 `min_importance_scores_per_module`，默认要求每个模块至少经历 2 次重要性打分。

训练开始前会根据本次训练预计的打分次数、模块数量和覆盖目标，自动计算所需的有效分组规模。如果用户设置的 `importance_group_size` 已满足覆盖要求，则保持不变；如果不满足，则自动增大到计算后的值。

同时记录 `planned_scoring_events`、`planned_importance_updates`、`effective_importance_group_size`、`effective_score_module_batch_size` 等字段，便于检查覆盖计划是否达标。

最新实验中，打分覆盖问题已明显改善。

## 标题：象限收益统计口径存在归因偏差

### 原因/现象

早期图表中，象限收益使用“当前 step 到未来 eval 的全局验证损失下降”作为模块收益标签。同一个 step 的所有模块共享同一个全局标签，因此无法真正反映单个模块或象限的因果贡献。

当某个象限刚好在全局变差的训练窗口中占比较高时，该象限会被错误地归因为负收益。这曾导致“高 I 高 P 象限收益反而更差”的异常现象。

### 解决方案

将主要收益指标改为模块级反事实收益，即使用模块当前的重要性消融结果作为 `module_gain`。该指标更接近“关闭该模块后损失变化”的模块级贡献。

图表中保留全局 loss decrease 作为辅助诊断字段，但不再将其作为象限策略好坏的主要判断依据。

最新图表中，`high_I_high_P` 的模块级收益显著高于其他象限，说明该统计口径更符合理论预期。

## 标题：象限划分早期受大量相同分数影响

### 原因/现象

早期训练阶段，大量模块的 `ema_I` 可能为 0。如果直接使用分位数阈值并采用“大于等于阈值”的方式判断 high-I，会把很多实际没有区分度的 0 分模块划入 high-I。

这会导致早期象限分布异常，影响 rank 分配和策略分析。

### 解决方案

将 high-I 和 high-P 的判断方式从“分数是否大于等于阈值”改为“按排序选取 top 比例”。

这样可以避免大量相同值导致的伪 high-I，同时保持分位数划分的稳定性。

## 标题：P 分数与 I 分数耦合过强

### 原因/现象

早期 P 分数计算中包含较强的 `ema_I` 任务改进代理项，导致 P 与 I 高度相关。这样一来，I/P 象限在实际效果上会退化为近似一维排序，P 无法提供足够独立的信息。

在图表上表现为 I/P top-k 重叠较高，象限分离度不足。

### 解决方案

新增 `plasticity_task_weight` 参数，将 P 计算中来自 `ema_I` 的权重降低，默认设置为 0.1。

这样可以减少 I 对 P 的直接泄漏，使 P 更多反映梯度、优化器方向、参数更新和训练资源利用效率等信息。

最新实验中，象限收益解释已经更合理，但仍建议继续观察 I/P 相关性是否进一步下降。

## 标题：low-I/low-P 模块更新策略过于激进

### 原因/现象

早期版本中，`low_I_low_P` 象限模块会被设置为近似永久不更新。这在重要性估计不充分或早期分数不稳定时，容易造成误杀。

对于小样本任务，早期误判可能长期影响训练效果。

### 解决方案

将 `low_I_low_P` 从近似永久不更新改为温和低频更新，并新增 `low_i_low_p_update_interval` 参数，当前默认值为 32。

这样既保留了低优先级模块减少更新的策略，又避免模块被过早锁死。

## 标题：模块级 early stop 冻结影响学习能力

### 原因/现象

早期实验中，模块级 early stop 会冻结较多 LoRA 模块。冻结模块过多时，模型仍保留一定 rank，但这些模块不再有效更新，可能造成有效学习能力下降。

该问题在 RTE 小数据任务上尤其明显，容易加剧欠拟合或错误剪枝。

### 解决方案

在当前主实验脚本中加入并启用 `disable_module_early_stop`，暂时关闭模块级 early stop 冻结。

后续如果重新启用 early stop，建议配合更稳定的 I/P 分数、更长观察窗口和更保守的冻结条件。

## 标题：keep/prune 图缺乏判别力

### 原因/现象

当前配置中启用了 `avoid_zero_rank`，同时关闭了模块 early stop，并将 low-I/low-P 改为低频更新。因此所有模块最终基本都被保留，`final_retention_ratio` 接近 1。

这种配置更适合验证 rank 分配和更新频率策略，但不适合用来分析真实剪枝效果。

### 解决方案

当前阶段将 keep/prune 图作为辅助图，而不是主要结论来源。

如果后续需要验证真实剪枝能力，应单独设计剪枝实验，例如允许部分模块 rank 降为 0，或设置更严格的总 rank budget，再观察不同象限的保留率和性能影响。

## 标题：rank 预算分配较保守，模块保留比例偏高

### 原因/现象

当前实验中 `target_rank=8`，总 rank 预算较高，最终 active rank 总量接近预算上限。所有模块基本都保留非零 rank，因此策略更偏向“资源重分配”，而不是“强剪枝”。

这有利于获得较高准确率，但不利于证明 IPD 策略在低预算下的压缩能力。

### 解决方案

当前配置可作为高准确率版本保留。

如果目标转向效率或压缩，应增加低预算对照实验，例如降低 `target_rank` 或设置更严格的 `total_rank_budget`，并观察准确率、rank 分布和象限收益变化。

## 标题：实验日志可能混入历史运行

### 原因/现象

早期实验中，多次运行可能复用同一个输出目录。由于日志文件以追加方式写入，容易出现 training log、module scores 和图表结果混杂，影响分析判断。

### 解决方案

将实验脚本改为每次运行自动生成带时间戳的输出目录。

这样可以保证每次实验的日志、模型、图表和配置互相隔离，便于复现和比较。

## 标题：图表指标含义需要区分主指标和辅助指标

### 原因/现象

在多轮实验中，部分图表的名称和指标容易让人误以为它们直接代表模块因果收益。例如 `global_loss_decrease` 反映的是整体训练曲线变化，不适合作为模块级结论。

如果不区分主指标和辅助指标，容易误读图表。

### 解决方案

当前建议将以下指标作为主分析依据：

- `avg_module_gain`：模块级反事实收益，优先用于判断象限是否符合理论预期。
- `avg_module_gain_per_rank`：单位 rank 的模块收益，用于判断资源效率。
- `avg_I` 和 `avg_P`：用于解释象限分配是否合理。

以下指标作为辅助诊断：

- `avg_global_loss_decrease`：用于观察整体训练窗口变化，不用于直接判断模块收益。
- `final_retention_ratio`：只有在真实剪枝实验中才有强解释力。

## 标题：当前最佳版本效果总结

### 原因/现象

最新实验目录 `ipd_lora_rte_seed42_v4_20260526_161159` 中，RTE 验证集最佳准确率达到 0.8809，final accuracy 也为 0.8809，说明 best checkpoint 与 IPD 运行态恢复已经生效。

从象限统计看，`high_I_high_P` 的 `avg_module_gain` 明显高于其他象限，说明模块级收益口径下，高 I 高 P 象限已基本符合预期。

不过训练后期仍存在明显过拟合，真实最后一轮验证结果低于最佳结果。当前结果依赖 best checkpoint 回载来保证最终汇报。

### 解决方案

当前版本可以作为阶段性有效版本保留。

后续建议围绕三个方向继续推进：

1. 加入验证集 early stopping，减少后期无效训练。
2. 继续降低 I/P 耦合，提升 P 的独立解释能力。
3. 设计低预算或允许 rank 为 0 的对照实验，专门验证剪枝能力。

## 阶段性进展总结

本阶段主要完成了以下改进：

- 修复训练模式恢复问题。
- 修复 final evaluation 未使用 best checkpoint 的问题。
- 增加 IPD 运行态快照与恢复机制。
- 提升重要性打分覆盖率。
- 改进象限划分方式，减少 ties 偏置。
- 降低 P 对 I 的直接依赖。
- 将主要收益图从全局 loss 变化改为模块级反事实收益。
- 使用时间戳输出目录隔离实验结果。

当前版本在 RTE 上已达到约 88.1% 验证准确率，明显优于早期版本，并且象限图的解释性也更符合预期。

后续工作重点不再是修复基础实现问题，而是进一步提升训练稳定性、验证低预算效率，以及将当前结果整理成可复现的正式实验对照。

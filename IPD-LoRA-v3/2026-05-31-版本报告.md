# IPD-LoRA v3/v4 阶段性进展汇报

日期：2026-05-31

本文档围绕近期 IPD-LoRA 在 GLUE RTE 任务上的迭代过程进行汇总。与上一版“问题清单”不同，本版按照已经完成的具体进展组织内容，每一节说明该进展的背景原因、实验现象、解决方案和当前效果，便于后续整理为 PPT。

## 进展一：修复训练模式恢复问题

### 原因/现象

IPD-LoRA 在计算模块重要性时，需要临时将模型切换到评估模式，以保证打分过程稳定。但早期版本中，重要性打分结束后没有显式恢复训练模式。

这会导致后续部分训练步骤仍然处于评估模式下执行。对于包含 dropout 的训练过程，这会改变模型实际训练行为，使训练和预期配置不一致，并可能影响泛化表现。

### 解决方案

在每次 IPD 打分逻辑结束后，显式调用 `model.train()`，确保模型回到训练模式。

该修复属于基础实现层面的修正，不改变模型结构、参数量和推理开销，但可以避免训练行为偏离预期。

### 当前效果

训练过程中的模式切换逻辑已经闭环。后续实验不再受该问题影响，训练过程稳定性更可控。

## 进展二：修复 final evaluation 未使用最佳 checkpoint 的问题

### 原因/现象

早期实验中，训练过程中虽然会保存 `best_model`，但训练结束后的 final evaluation 和 final model 导出仍然使用最后一轮模型。

RTE 数据量较小，训练后期容易过拟合，因此最后一轮模型经常低于训练过程中的最佳模型。这会导致最终汇报结果低估模型真实能力。

### 解决方案

训练过程中记录验证集表现最好的模型权重，并在训练结束后回载最佳权重，再进行最终评估和模型导出。

后续进一步发现，IPD-LoRA 的运行状态不仅包含模型权重，还包括 `active_rank`、`target_rank`、`update_interval`、`quadrant`、`ema_I`、`ema_P` 等动态状态。这些状态不是普通模型参数，仅恢复 `state_dict` 不足以恢复完整策略状态。

因此补充了 IPD 运行态快照机制：当验证集表现刷新最佳结果时，同时保存模型权重和 IPD 运行态；训练结束回载 best checkpoint 时，也同步恢复 IPD 运行态。

### 当前效果

最新实验中，`best_eval_accuracy` 与 `final_eval_accuracy` 已保持一致，均达到约 88.1%。这说明最终汇报已经能够反映最佳 checkpoint 的真实性能，而不是被最后一轮过拟合结果拖低。

## 进展三：增加 IPD 运行态快照与恢复机制

### 原因/现象

IPD-LoRA 与普通 LoRA 的一个重要区别是：训练过程中每个模块的 active rank、更新频率、象限归属和 I/P 分数都会动态变化。

这些运行态直接影响模型的实际前向路径和后续策略分析。如果只保存模型参数，而不保存 IPD 运行态，就可能出现“权重来自 best checkpoint，但 rank 和象限状态来自最后一轮”的不一致问题。

### 解决方案

新增 IPD runtime state 保存与恢复逻辑。保存内容包括：

- 每个模块的 active rank 和 target rank；
- 每个模块的 update interval；
- 每个模块当前所属象限；
- I/P 当前值与 EMA 值；
- early stop 相关状态；
- I/P 排名与标准化分数。

在 `best_model` 和 `final_model` 目录中写入 `ipd_runtime_state.json`，确保 checkpoint 不只包含权重，也包含策略状态。

### 当前效果

当前版本 final model 的结果已经与 best checkpoint 对齐。该机制也为后续复现实验、分析不同 checkpoint 的 rank 分布和象限状态提供了基础。

## 进展四：提升重要性打分覆盖率

### 原因/现象

早期版本中，每次 IPD 打分只覆盖一部分 LoRA 模块，而总打分次数较少，导致部分模块在整个训练过程中从未获得有效重要性分数。

这会造成两个问题：

- 没有被充分打分的模块可能被错误划入低重要性象限；
- 象限分布和 rank 分配会受到系统性偏差影响。

### 解决方案

新增 `min_importance_scores_per_module` 参数，默认要求每个模块在一次训练中至少经历 2 次重要性打分。

训练开始前会根据以下信息自动计算覆盖计划：

- 本次训练预计会发生多少次 IPD scoring；
- 其中有多少次会真正更新 importance；
- LoRA 模块总数；
- 每个模块期望的最低打分次数。

如果用户设置的 `importance_group_size` 已经满足覆盖要求，则保持不变；如果不满足，则自动增大到计算后的有效值。同时记录覆盖计划字段，便于实验后检查。

### 当前效果

最新实验中，计划打分事件和实际模块覆盖明显改善，不再出现整层模块长期未被打分的问题。象限划分和 rank 调整的基础数据更加可靠。

## 进展五：改进象限划分方式，减少 ties 偏置

### 原因/现象

早期训练阶段，很多模块的 `ema_I` 可能都是 0。如果直接使用分位数阈值，并用“大于等于阈值”的方式判断 high-I，就会把大量没有实际区分度的模块划入 high-I。

这种情况会导致早期象限分布失真，并进一步影响 rank 分配和策略解释。

### 解决方案

将 high-I 和 high-P 的判定方式从“是否大于等于分位数阈值”改为“按排序选取 top 比例”。

这种方法不再依赖阈值处的相等比较，可以减少大量相同分数带来的伪 high-I 或伪 high-P 问题。

### 当前效果

象限划分在训练早期更稳定，减少了由于大量 0 分或相同分数造成的异常象限分布。后续图表中 high-I/high-P 的解释性更强。

## 进展六：降低 P 对 I 的直接依赖

### 原因/现象

早期 P 分数计算中包含较强的 `ema_I` 任务改进代理项。这会导致 P 与 I 高度相关，使 I/P 象限在实际效果上退化为近似单一排序。

当 P 与 I 过度耦合时，P 无法有效表达“可塑性”这一独立信息，象限划分也难以区分“高重要但低可塑”和“低重要但高可塑”等情况。

### 解决方案

新增 `plasticity_task_weight` 参数，用于控制 P 分数中来自 `ema_I` 的权重。当前默认值设置为 0.1，相比早期版本明显降低。

这样可以让 P 更多反映梯度方向、优化器更新、参数变化和训练资源利用效率，而不是重复表达 I 的信息。

### 当前效果

最新实验中，象限收益解释更符合预期。`high_I_high_P` 在模块级收益指标上明显高于其他象限，说明 I/P 象限已经能够更好地服务策略分析。

后续仍建议继续观察 I/P 相关性，判断 P 是否已经具备足够独立的信息量。

## 进展七：将主要收益图从全局 loss 变化改为模块级反事实收益

### 原因/现象

早期象限收益图使用“当前 step 到未来验证点的全局 loss 变化”作为收益标签。该指标是全局训练曲线变化，同一个 step 的所有模块共享同一个值，不能真实反映单个模块或某个象限的因果贡献。

这曾导致图表出现反直觉现象：理论上应当更重要的 high-I/high-P 象限，在图中反而显示为更低收益。

### 解决方案

将图表中的主收益指标改为模块级反事实收益 `module_gain`。该指标来自模块重要性消融结果，含义更接近“如果移除该模块，会造成多大损失变化”。

同时保留 `avg_global_loss_decrease` 作为辅助诊断字段，用来观察整体训练窗口变化，但不再将其作为判断象限好坏的主指标。

### 当前效果

最新实验中，`high_I_high_P` 的 `avg_module_gain` 明显高于其他象限，符合理论预期。

这说明图表解释性已经显著改善：主图不再被全局训练波动误导，而是更接近模块级贡献分析。

## 进展八：调整 low-I/low-P 模块更新策略

### 原因/现象

早期版本中，`low_I_low_P` 象限模块会被设置为近似永久不更新。该策略在重要性估计不充分时过于激进，容易因为早期误判而长期抑制某些模块学习。

尤其在小样本任务中，早期评分噪声较大，过早锁死模块可能降低模型后续适应能力。

### 解决方案

将 `low_I_low_P` 从近似永久不更新改为温和低频更新，并新增 `low_i_low_p_update_interval` 参数。当前默认值为 32。

该策略仍然降低低优先级模块的更新频率，但避免模块被完全排除在学习过程之外。

### 当前效果

训练过程更加保守和稳定，降低了错误剪枝或错误冻结带来的风险。当前版本更适合验证“动态资源分配”策略，而不是激进剪枝策略。

## 进展九：关闭模块级 early stop 冻结

### 原因/现象

早期实验中，模块级 early stop 会冻结较多 LoRA 模块。被冻结的模块虽然可能仍保留 rank，但不再有效更新，会削弱模型实际学习能力。

在 RTE 这类小数据任务上，如果 early stop 依据的 I/P 分数还不够稳定，冻结策略容易造成欠拟合或错误剪枝。

### 解决方案

在当前主实验配置中启用 `disable_module_early_stop`，暂时关闭模块级 early stop 冻结。

当前阶段优先保证模型充分训练和策略可解释性，避免 early stop 机制引入额外干扰。

### 当前效果

当前实验中不再出现大量模块被提前冻结的问题。模型准确率提升到约 88.1%，说明关闭模块冻结有助于稳定当前任务表现。

后续如果重新启用 early stop，需要在更稳定的 I/P 估计基础上设计更保守的冻结条件。

## 进展十：使用时间戳输出目录隔离实验结果

### 原因/现象

早期实验可能复用同一个输出目录。由于训练日志、模块分数和图表文件会持续写入，复用目录容易造成不同实验结果混杂。

一旦日志混杂，训练曲线、象限统计和最终指标都可能被误读。

### 解决方案

将实验脚本改为每次运行自动生成带时间戳的输出目录。

每次实验都会独立保存配置、训练日志、模块分数、图表、best model 和 final model。

### 当前效果

后续每次实验结果都可以清晰追踪和复现。不同版本之间可以直接对比，减少了分析过程中的数据污染风险。

## 进展十一：区分主分析指标与辅助诊断指标

### 原因/现象

多轮实验中发现，部分图表指标容易被误读。例如 `avg_global_loss_decrease` 反映的是整体训练窗口变化，不适合作为模块级策略优劣的主判断依据。

同时，当前配置基本保留所有模块，因此 `final_retention_ratio` 接近 1。这说明 keep/prune 图在当前设置下判别力有限，不能直接证明剪枝能力。

### 解决方案

重新明确图表指标的解释层级：

- `avg_module_gain`：作为主要收益指标，用于判断象限是否符合理论预期；
- `avg_module_gain_per_rank`：作为资源效率指标，用于观察单位 rank 收益；
- `avg_I` 和 `avg_P`：用于解释象限分配是否合理；
- `avg_global_loss_decrease`：仅作为整体训练趋势的辅助诊断；
- `final_retention_ratio`：仅在真实剪枝实验中作为主要指标。

### 当前效果

当前图表更适合服务 PPT 汇报：主结论可以围绕模块级收益展开，辅助指标用于解释训练过程和策略边界，避免把全局训练波动误读为模块因果贡献。

## 进展十二：当前最佳版本性能达到阶段性目标

### 原因/现象

经过上述修复和策略调整后，最新版本在 GLUE RTE 验证集上达到约 88.1% accuracy。相比早期 82% 到 85% 左右的结果，性能有明显提升。

最新实验中，best accuracy 与 final accuracy 均为 0.8809，说明最终结果能够正确反映最佳 checkpoint 表现。

从象限统计看，`high_I_high_P` 的模块级收益明显高于其他象限，说明当前策略的解释性也比早期版本更合理。

### 解决方案

当前配置可以作为阶段性有效版本保留，用于后续论文实验、PPT 展示或更多任务迁移验证。

同时需要注意，训练后期仍然存在过拟合现象。虽然 best checkpoint 回载可以保证最终汇报结果，但训练后半段仍有优化空间。

### 当前效果

当前版本已经完成从“实现修复”到“策略可解释性改善”的阶段性转变。后续工作重点可以从修 bug 转向验证效率、泛化性和可复现性。

## 后续工作建议

1. 增加基于验证集的 early stopping，减少后期无效训练。
2. 继续观察 I/P 相关性，评估 P 是否具备足够独立信息。
3. 设计低预算实验，例如降低 `target_rank` 或设置更严格的 `total_rank_budget`。
4. 单独设计允许 rank 为 0 的剪枝实验，用于验证真实 keep/prune 能力。
5. 将当前 RTE 结果迁移到更多 GLUE 子任务，验证策略是否具有普适性。
